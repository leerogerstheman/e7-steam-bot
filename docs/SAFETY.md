# 安全边界与风险说明

## 一句话

本项目是「**看着屏幕、动鼠标**」的自动化 —— 和坐在电脑前的真人做的是同一件事，
只是不知疲倦。它不碰游戏进程内部。**但这不等于不会被封。**

---

## 1. 反作弊：UNCHEATER（内核级）

Steam 商店页（AppID 5019180）明确标注：

> **Uses Kernel Level Anti-Cheat: UNCHEATER**

- UNCHEATER 由 **Wellbia** 出品，与 **XIGNCODE3 同厂**（XIGNCODE3 被大量韩系网游使用）
- **内核级**意味着它以驱动形式加载，权限高于普通用户态程序，
  具备扫描进程、内存、模块、句柄的能力
- 确认**不使用 VAC**（VAC 只作用于 Valve 自家反作弊的游戏）

### 这意味着什么

| 行为 | 风险 | 本项目 |
|---|---|---|
| 读取/写入游戏进程内存 | 极高，内核反作弊的**主要检测目标** | ❌ 绝不 |
| DLL 注入 / API Hook / 调试器附加 | 极高 | ❌ 绝不 |
| 修改游戏文件、封包 | 极高 | ❌ 绝不 |
| 驱动级模拟输入（interception / kmbox 等） | 高，且会加载**第三方内核驱动**，极易被识别 | ❌ 绝不 |
| `SendMessage` / `PostMessage` 投递窗口消息 | 中（会被识别为异常输入源） | ❌ 不用 |
| **`SendInput` 合成系统输入 + 屏幕截图** | 相对最低 | ✅ 采用 |

### 为什么 `SendInput` 相对安全

`SendInput` 把事件插入 **Windows 系统输入队列**，与真实键盘鼠标产生的硬件事件
走同一条路径、结构完全一致。从游戏的角度看，它读到的是正常的输入状态
（Raw Input / `GetAsyncKeyState`），**没有可区分的来源标记**。

对比之下，`SendMessage(WM_LBUTTONDOWN)` 这类窗口消息投递，游戏根本不会消费
（DirectX 游戏普遍走 Raw Input，不读窗口消息队列），既无效又异常。

**但请注意**：`SendInput` 只解决"输入来源像不像真的"，
不解决"行为模式像不像人"。这正是本项目做拟人化的原因 ——

- 鼠标按三次贝塞尔曲线移动，速度用 smoothstep 缓动，距离越远越慢
- 落点加高斯抖动（默认 σ=2.5px）
- 按下时长、点击前后停顿全部随机区间取值
- 主循环 tick 间隔随机抖动（±25%），不做毫秒级固定节拍

## 2. 行为层面的风险（这部分更重要）

内核反作弊之外，厂商还有**服务端行为分析**。以下模式很容易被标记：

| 风险行为 | 本项目的应对 |
|---|---|
| 24 小时不间断运行 | `safety.max_runtime_minutes`（默认 8 小时）到点自动停 |
| 固定毫秒级节拍 | 所有延时随机化 |
| 鼠标瞬移、轨迹是直线 | 贝塞尔曲线 + 缓动 |
| 从不休息 | **建议你自己再加随机休息**：配置里把 `max_runtime_minutes` 调小，跑完手动歇一阵 |
| 点击位置像素级完全一致 | 落点抖动；但如果你把 `move_jitter_px` 设成 0 就没了，别这么干 |

### 使用建议

1. **只在小号上试验。** 主力号别碰。
2. **不要在活动/竞技场/PvP 期间挂机** —— 那是最容易被举报和人工审核的场景。
3. **单次运行时间短一点。** 参考项目跑 8 小时；如果你想更保守，调成 2~3 小时。
4. **人在旁边。** 至少保证 F12 一按就能停。
5. **不要多开。** 官方对多开的态度未查证到，内核反作弊常见单实例限制，
   多开还会显著提高被注意的概率。

## 3. 技术上的安全设计

### 急停

- 默认 **F12** 全局急停。刻意**不用 ESC** —— ESC 在第七史诗里是打开菜单的游戏键
  （参考项目 E7-helper 用 ESC，会误触菜单）
- 检查粒度很细：`Mouse.move_to` 的每一段插值都会检查停止标志，不是等一步做完才响应
- 暂停键 **F9** 可随时暂停/继续

### 前台保护

默认 `window.pause_when_not_foreground = true`：游戏一旦失焦就暂停。
两个好处：输入一定送到正确的窗口；不会在别的程序上乱点。
（`SendInput` 只作用于前台窗口，失焦时点击本来也无效。）

### 自动停机

| 触发条件 | 配置项 | 默认 |
|---|---|---|
| 运行时长超限 | `safety.max_runtime_minutes` | 480 分钟 |
| 连续认不出场景 | `safety.unknown_scene_timeout` | 90 秒 |
| 连续出错 | `safety.max_consecutive_errors` | 8 次 |

自动停机时会往 `logs/frames/` 存一张调试图，方便定位"当时到底停在哪个界面"。

### 致命弹窗

`repeat_stage` 遇到 `common/popup_no_stamina`（体力不足）、
`common/popup_inventory_full`（背包已满）会**主动停机等人工处理**，
而不是盲目重试空转。

### dry-run

`run --dry-run`（或配置 `safety.dry_run = true`）只做识别和日志，**一次都不点击**。
上线前必须先用它确认所有判断都正确。

## 4. 显示器保活

DXGI Desktop Duplication 复制的是**显示器输出**。显示器一休眠，截图就变黑，
脚本会误判为"游戏卡住"。参考项目 E7-helper 的 README 也专门提醒了这点
（"make sure the monitor is TURNED ON AT ALL TIMES"）。

本项目启动时会调用：

```python
SetThreadExecutionState(ES_CONTINUOUS | ES_DISPLAY_REQUIRED | ES_SYSTEM_REQUIRED)
```

阻止系统休眠和显示器关闭，退出时恢复。但**不要手动关屏**。

另外：游戏窗口**不能最小化**（最小化后 DXGI 拿不到内容）。
被其他窗口部分遮挡一般没问题。
