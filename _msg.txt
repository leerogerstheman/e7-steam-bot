按真实 Demo 实测修正配置，并修复一个实测抓到的窗口误锁 bug

对已安装的 Steam Demo（AppID 5129800）做只读二进制分析，实测结论：
- 窗口标题 = "EpicSeven (Steam)"（exe 内 UTF-16 字符串）
- 主程序 = EpicSeven_Steam.exe
- 渲染 API = OpenGL/GLES（OPENGL32/EGL/GLESv2），不是 DirectX  ← 推翻旧推断
- 引擎 = cocos2d-x + SDL2 + Lua（SmokeGate 包装为 YUNA2D）
- 权限 = asInvoker，游戏本身不请求提权                      ← 推翻旧推断
- DPI = 运行时自行调用 SetProcessDPIAware，是 DPI 感知
- 反作弊 = UNCHEATER 进程内加载；目录内有独立加载器 ucldr_Epic7_SM_loader_x64.exe

配置修正（config/default.toml + e7bot/config.py）：
- title_patterns 加入实测精确值；exe_patterns 加入 EpicSeven_Steam
- 新增 exclude_title_patterns / exclude_exe_patterns，排掉反作弊加载器与崩溃处理器
- 新增 min_title_coverage，防"游戏名只是长标题里一小段"的假阳性

实测抓到的真 bug（跑 doctor 时锁到了浏览器窗口）：
  标题 `第七史诗steam端要上线了… — DeepSeek Harness` 被 `第七史诗` 模式命中，
  脚本把浏览器当成游戏窗口 —— 失败现象却是"识别不到场景"，极难定位。
修法：匹配改两级 —— 进程名优先；仅标题命中时要求游戏名覆盖标题 >=50%，
并在拒绝时打印原因。有回归测试用真实浏览器标题锁住该行为。
